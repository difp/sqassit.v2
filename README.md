# SQASSIT v2 — Rust migration

This repository tracks the migration of [SQASSIT](https://github.com/difp/sqassit) to Rust. The reference implementation in `legacy/` is a snapshot of commit `736a779f59d9e13d7e3a0f0401d6dd1c642cfada`. Its tests, static assets, and deployment documentation remain available for compatibility checks.

**Status:** migration in progress. The Python implementation remains the reference and is not yet replaced. See [the migration plan](RUST-MIGRATION-PLAN.md).

## Rust preview

With Rust installed, run `cargo run` from the repository root and open `http://127.0.0.1:8000`. The preview serves the original pages and implements much of the API, but parity and real Telegram delivery are not yet verified. Set `BOT_TOKEN`, `COACH_TELEGRAM_ID`, and optionally `DB_PATH` to enable authenticated endpoints. With the opt-in bot, booking and cancellation trigger best-effort Telegram notifications. `/readyz` checks SQLite and Telegram Bot API (`getMe`, cached for 60 seconds) and returns 503 with a Russian detail when either is unavailable; without `BOT_TOKEN` it reports the database as unavailable. This build must not be deployed as a replacement. `SQASSIT_BIND` and `SQASSIT_STATIC_DIR` override the bind address and static directory for development; `AVATAR_CACHE_DIR` selects the avatar disk cache (default `./data/cache/avatars`).

Run `cargo test --locked` for the current Rust checks. Progress and remaining work are documented in [MIGRATION-STATUS.md](MIGRATION-STATUS.md).

For a local release smoke test, run `cargo build --release --locked` followed by `python3 tests/release_smoke.py target/release/sqassit`. The test stages the binary and static files in a temporary directory, starts it without credentials, checks its HTTP responses and stops it. CI runs the same check. This is a packaging check, not production deployment validation.

For a synthetic large-directory timing, run `cargo test --release --locked --test search_benchmark -- --ignored --nocapture`. It seeds 50,000 players in memory and prints timings; it is not a production load test.

The Python/Rust contract tests use separate temporary databases and suppress Telegram background tasks. Install `legacy/requirements.txt` and `httpx2==2.14.0` in a Python 3.12 environment, then run `SQASSIT_REFERENCE_PYTHON=/path/to/python cargo test --locked --test python_contract --test schema_contract --test bot_contract --test reminder_contract --test cleanup_contract --test final_enrollment_contract --test match_notify_contract --test chat_notify_contract --test headers_contract --test training_delete_contract --test application_notify_contract --test role_notify_contract -- --ignored`. They compare HTTP workflows and selected final data, the migration of a synthetic old SQLite schema, security and cache headers, outgoing Telegram API calls for the ported bot commands and callbacks, one training-reminder tick, expired-notification cleanup including a transient deletion failure, preliminary-to-final enrollment replacement, match notifications, chat notifications, training-deletion notifications, coach-application notifications, and role notices. Timestamps and scoped-token values are normalized, and fake message IDs follow the same sequence, so this is not complete parity verification. CI runs them separately. The Python SQLite worker may require running outside restrictive sandboxes.

Experimental training reminders can be enabled explicitly with `SQASSIT_ENABLE_REMINDERS=true`, a test bot token and a test database. This sends real Telegram messages. Run at most one scheduler per database. This preview is not suitable for production. `BOT_PROXY` can configure HTTP or SOCKS proxy access.

For a dedicated **test bot only**, `SQASSIT_ENABLE_BOT=true` enables update handling. `BOT_MODE=polling` checks Telegram for an existing webhook and refuses to start if one is active or its status cannot be checked; it never deletes the webhook or drops updates. `BOT_MODE=webhook` requires `WEBHOOK_BASE_URL` and a secret of at least 32 characters in `WEBHOOK_SECRET`. Set `SQASSIT_REGISTER_WEBHOOK=true` only when you intentionally want this preview to replace the bot’s registered Telegram webhook. Unrelated updates are ignored; failed supported updates may be retried. Do not run this alongside another poller or use a production bot: the migration and event notifications are incomplete.
